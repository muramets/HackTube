# Create / Update / Delete Custom Video (CLI)

## Что это

Команда в терминале, через которую агент (Claude Code) готовит видео к публикации:
создаёт новое custom-видео, обновляет или удаляет существующее — обложка, название, описание, теги,
плейлист, версия упаковки. Результат неотличим от того, что делается руками в приложении.

Публикации на YouTube нет — только подготовка внутри hacktube.

## Зачем

- Агент уже умеет придумывать упаковку (название, описание, теги, обложку), но переносить её в приложение
  приходилось руками: открыть модалку, скопировать поля, загрузить и пережать картинку.
- CLI убирает этот ручной шаг: «упаковал → одной командой положил в приложение» — и так же одной командой
  поправил упаковку уже созданного видео.

## Текущее состояние

- ✅ Создание видео: обложка, название, описание (в т.ч. из файла), теги; сразу в плейлист и/или как v.1.
- ✅ Обновление видео: меняются только переданные поля; сохраняется черновиком или новой версией —
  ровно как кнопки «Save draft» / «Save as new version» на вкладке Packaging.
- ✅ Плейлисты у существующего видео: добавить в один или несколько, убрать, перенести одной командой.
  Работает и для YouTube-видео (их упаковку CLI не трогает). Новые видео встают в конец плейлиста.
- ✅ Подниша: назначить (`--subniche`) или снять (`--clear-subniche`); не создаёт черновик/версию → [Subniches](./subniches.md).
- ✅ Удаление видео — так же полно, как в приложении: файлы, история, трафик, Home, плейлисты.
- ✅ Большие обложки уменьшаются автоматически (до 1280px, ≤ 2 MB), оригинал не трогается.
- ✅ Список каналов и плейлистов по названиям; канал можно не указывать — он находится по плейлисту или видео.
- ✅ Предпросмотр по умолчанию: без флага подтверждения ничего не записывается.
- ⚠️ Уменьшение обложки работает только на macOS; на Linux большие обложки отклоняются с понятной ошибкой.

Как пользоваться — `scripts/README.md` (индекс всех CLI проекта) или `--help`.

## User flow

1. Пользователь говорит агенту: «создай видео в плейлисте Slow Life November, обложка ./cover.jpg, сохрани как v.1».
2. Если агент не знает названий — смотрит список каналов и плейлистов.
3. Агент запускает команду в режиме предпросмотра — видит план: канал, поля, обложку (и что она будет уменьшена).
4. Агент запускает ту же команду с подтверждением — видео создаётся, команда печатает его ID.
5. Позже: «поменяй обложку и название у этого видео, сохрани новой версией» — та же команда с ID видео.
   Старая обложка уходит в историю обложек, прошлая версия закрывается, новая становится активной.
6. «Удали это видео» — команда сначала показывает, что именно удалится (файлы, снэпшоты, плейлисты),
   и удаляет только после подтверждения.
7. Если в браузере в этот момент открыта страница видео — приложение увидит, что данные изменились,
   и не перезапишет их молча.

## Technical Implementation

- **CLI:** `scripts/create-custom-video.mjs` — admin SDK + Application Default Credentials,
  dry-run по умолчанию, `--execute` для записи. Паттерн как у `scripts/move-video-to-channel.mjs`.
- **Режимы и флаги** (полный список — `--help`):
  - `--list [--channel <name|id>]` — каналы и их плейлисты с ID и количеством видео.
  - создание: `--title` + (`--channel` и/или `--playlist`), опционально `--description | --description-file`,
    `--tags "a,b,c"`, `--thumbnail`, `--playlist-only`, `--save-version`. `--playlist` можно повторять.
  - обновление: `--video <id>` + любые из полей выше (кроме `--playlist-only`) + `--remove-playlist` (повторяемый).
    Поля упаковки — только custom-видео; плейлисты — любое видео.
  - удаление: `--delete --video <id>` (несовместимо с флагами полей). Любое видео, не только custom.
  - `--user <uid>` — определяется автоматически, если в проекте один пользователь.
- **Чистые функции** (компилируются в `functions/lib/shared/`, CLI импортирует оттуда — single source of truth):
  - `shared/customVideo.ts` — `buildCustomVideoDoc` (создание), `buildCustomVideoUpdate` (обновление),
    `resolveNextVersionNumber`, `needsThumbnailDownscale`, `assertThumbnailWithinLimit`,
    `resolveThumbnailContentType`, `buildCoverStoragePath`, `parseTagList`, `prependUniqueId` (Home),
    `appendUniqueId` (плейлист), `planPlaylistMembership` (что добавить/убрать + защита от «невидимого» видео).
  - `shared/packagingPeriods.ts` — `ensureActivePeriods`, `closeAllPeriods`, `addNewActivePeriod`.
    `VersionService` (вкладка Packaging) делегирует сюда.
  - Тесты: `shared/__tests__/customVideo.test.ts`, `shared/__tests__/packagingPeriods.test.ts`.
- **Создание** — `users/{uid}/channels/{channelId}/videos/custom-{timestamp}`, поля как в `useAddCustomVideo`.
  Фальшивый `viewCount` (UI ставит `'1000000'`) намеренно не записывается.
  `--save-version` → `packagingHistory: [v1]` с открытым `activePeriods`, `activeVersion: 1`, `currentPackagingVersion: 2`.
  Home: id в начало `settings/videoOrder.order`; с `--playlist-only` — `isPlaylistOnly: true`, без Home.
- **Обновление** — одна транзакция над документом видео (`buildCustomVideoUpdate`):
  - draft: у всех версий закрываются открытые периоды, `isDraft: true`, `activeVersion: 'draft'`.
  - `--save-version`: периоды закрываются, добавляется версия N (= `currentPackagingVersion`, но не занятая)
    с открытым периодом и снимком итоговых полей (+ A/B, localizations), `activeVersion: N`, `currentPackagingVersion: N+1`.
  - обложка: текущая уходит в `coverHistory` под своим `customImageVersion`, новая получает max+1.
  - `packagingRevision` +1 — открытая вкладка Packaging ловит `VERSION_MISMATCH` вместо тихой перезаписи.
  - Если меняются только плейлисты — документ видео не трогается.
  - Для опубликованных видео предупреждение: Packaging tab попросил бы Suggested Traffic CSV для закрытия
    прошлой версии (`closingSnapshotId`), CLI закрывает без снимка.
- **Удаление** — порядок как в `VideoService.deleteVideo`: файлы Storage под `videos/{videoId}/` →
  документ + все подколлекции (`recursiveDelete`, включая `traffic`, `history`) → id из `settings/videoOrder.order` →
  id из `videoIds` всех плейлистов канала (+ `updatedAt`). Dry-run показывает количество файлов, подколлекции и плейлисты.
- **Обложка:** путь `users/{uid}/channels/{channelId}/videos/{videoId}/{timestamp}_{fileName}`.
  Если шире 1280px или > 2 MB — копия через macOS `sips` (JPEG, качество 85) во временную папку.
- **Плейлисты:** текущие находятся через `array-contains` по `videoIds`. Добавление — id в **конец** `videoIds`
  (уже присутствующий id остаётся на месте), удаление — фильтр `videoIds` и `deprioritizedVideoIds`
  ([Deprioritized Videos](../playlists/deprioritized-videos.md)); + `updatedAt`, каждый плейлист в своей транзакции
  (`updateIdListInDoc` / `removeVideoFromPlaylistDoc`). Отличие от UI: `PlaylistService.addVideosToPlaylist` ставит видео в начало.
- **Порядок записи:** обложка → видео → Home → плейлист. При сбое после записи видео — видео уже есть,
  CLI печатает пройденные шаги, остальное доделывается в UI.
