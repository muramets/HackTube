# Deprioritized Videos (выцветание видео в плейлисте)

## Что это

Возможность «отодвинуть» видео внутри плейлиста, не удаляя его: карточка становится полупрозрачной
и почти чёрно-белой. Так видно, какой стиль канала формируют оставшиеся видео.

## Зачем

Пользователь собирает в плейлист будущие публикации, а потом замечает, что часть из них выбивается
из общего стиля. Удалять их рано, но хочется посмотреть на подборку без них. Выцветание — мягкий шаг
перед удалением: видео на месте, но взгляд на них не цепляется.

## Текущее состояние ← YOU ARE HERE

- ✅ **Deprioritize** в меню «⋯» у карточки внутри плейлиста; на выцветшем видео — **Restore priority**.
- ✅ Кнопка в плавающей панели для нескольких выделенных видео: если все уже выцветшие — восстанавливает, иначе выцветает.
- ✅ Выцветание действует только в этом плейлисте: на Home и в других плейлистах видео выглядит обычно.
- ✅ Видео не двигаются: остаются на своих местах в порядке плейлиста.
- ✅ При наведении карточка временно возвращает цвет, чтобы её можно было рассмотреть.
- ✅ Кнопка-глаз в шапке плейлиста (появляется, когда есть выцветшие) прячет их совсем; выбор запоминается для каждого плейлиста.
- ✅ Совместимо с режимом Freshness: эффекты не складываются, берётся более сильный.
- ✅ Если видео убрать из плейлиста или удалить — пометка снимается (в приложении и через CLI).

## User flow

1. В плейлисте пользователь открывает «⋯» у видео → **Deprioritize** (или выделяет несколько и жмёт кнопку-солнце в панели).
2. Карточка выцветает, в шапке появляется кнопка-глаз.
3. Глаз → выцветшие видео исчезают из сетки, видно «чистую» подборку. Ещё раз — возвращаются.
4. Передумал → **Restore priority** в меню или та же кнопка в панели.
5. Решил окончательно → удаляет видео из плейлиста обычным способом.

## Technical Implementation

- **Данные:** `users/{uid}/channels/{ch}/playlists/{id}.deprioritizedVideoIds: string[]` (подмножество `videoIds`).
  Запись — `PlaylistService.setVideosDeprioritized` (`arrayUnion` / `arrayRemove`), `updatedAt` не меняется
  (это настройка вида, а не содержимого). Хук — `usePlaylists().setVideosDeprioritized`.
- **Чистка:** `PlaylistService.removeVideosFromPlaylist` и `VideoService.deleteVideo` убирают id и из `deprioritizedVideoIds`;
  ленивая чистка «осиротевших» id на странице плейлиста — тоже. CLI (`scripts/create-custom-video.mjs`) —
  `removeVideoFromPlaylistDoc` при `--remove-playlist` и `--delete`.
- **Чистые функции:** `src/features/Playlists/utils/deprioritizedVideos.ts` —
  `DEPRIORITIZED_FADE`, `combineFadeStyles`, `buildPlaylistFadeMap`, `areAllDeprioritized`,
  `countDeprioritizedInPlaylist`, `mergeVisibleReorder`. Тесты рядом в `__tests__/`.
- **Визуал:** карточки получают `fadeMap` / `fadeStyle` (`VideoFadeStyle` из `src/features/Video/VideoCard.tsx`),
  тот же механизм, что раньше обслуживал только Freshness.
- **UI:** `src/features/Video/VideoCardMenu.tsx` (пункт меню), `src/features/Video/components/VideoSelectionFloatingBar.tsx`
  (`deprioritizeAction`), `src/pages/Playlists/PlaylistDetailPage.tsx` (fade map, кнопка-глаз, фильтр скрытия).
- **Состояние скрытия:** `filterStore.hideDeprioritized`, сохраняется в `pageStates['playlist:{id}']` как `freshnessMode`.
